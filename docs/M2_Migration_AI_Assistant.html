M2 Migration – AI Assistant (Ollama and Claude)

The migration is rule-based: the same exports and settings always give the same import file, and every decision is in the journal. The AI assistant does not change that. It reads a finished run and proposes decisions; a person accepts them, and they apply on the next run.

Claude by Google sign-in (no API key)

In AI settings, set Claude access to Sign in with Google (Google Cloud Vertex AI), type the Google Cloud project ID and keep the region global. The card below lists what is still missing, step by step:

  1. The Google Cloud CLI on this machine, once: sudo snap install google-cloud-cli --classic.
  2. A Google Cloud project with billing, the Vertex AI API on, and Claude enabled in Vertex AI Model Garden (Google bills the calls).
  3. Sign in with Google: Google's page opens in the browser; choose the account and allow access. The page updates by itself.
  4. The company setting that lets column headers and M2 codes go to Claude. Names, values and documents never leave this machine, whichever access is chosen.

The assistant then calls the same Claude model on Vertex AI with that Google sign-in. Switch back to API key at any time.

2. What stays on this machine

Client names, file and folder names, sample values, documents and the run summary never go to the cloud. Only column headers and M2 codes (type codes, holder codes, legal-form words) may go to Claude, and only when the company setting Allow column headers and M2 codes to go to Claude is on and ANTHROPIC_API_KEY is set. The code refuses a cloud call for any other task.
ModeBehaviour
ollama (default)Everything on Ollama.
autoOllama first; an answer below Ask Claude below confidence (0.6) on a header/code task is asked again to Claude.
claudeHeader/code tasks go to Claude first; documents, samples and summaries stay on Ollama.

The API key belongs in /data/migration_script/.env (ANTHROPIC_API_KEY=…), which bin/m2ctl.sh reads and git ignores.

Sorting list (your rules for the documents)

Files the rules cannot place would land at the top of the client's workspace. Write sorting list (card Document packages for Odoo) writes Document_Sorting.xlsx in the run folder with two sheets:

  • By M2 folder: one row per M2 folder, the quick way (the 30 largest folders hold most of these files).
  • To sort: one row per name pattern (same folder, same file name once numbers are masked), when one pattern needs another place.

Pick the Odoo folder as it is named in Odoo (e.g. 03 Banking / 03 Payment Orders), or an Odoo document type; Upload = No keeps the files in the archive. Save, then Apply my sorting list: the answers become rules kept in m2_config.json on this machine, applied at once and on every later run, before the keyword rules and the model. A pattern row wins over its folder row. The list holds client file names: keep it on this machine.

Document packages for Odoo

After Classify documents, the card Document packages for Odoo on the AI assistant tab writes the files to upload: zips of up to 90 MB with a manifest, in runs/<id>/packages/. Give the folder where the archive drive (Z:) is mounted or copied on this machine. A stopped build resumes where it was. Files not found are counted and listed in packages.json.

  1. Import the clients workbook in Odoo first.
  2. In Odoo, open Documents › Configuration › M2 Document Packages, create one entry per zip, upload it and press Import.
  3. Each file lands in its client's folder. The document type stays empty: set it when you check the file, so an old passport never replaces the current one or ticks a KYC requirement.
  4. Loading a package again skips the files already there. A power of attorney draft from the archive gets its signed document linked.

4. How far a suggestion can be trusted

  • The local model's own confidence is capped at 85 %: small models are not calibrated.
  • Column suggestions: only fields the file does not read yet are offered; the header must be close to the known header names of the field (embedding similarity ≥ 0.8 keeps the confidence, 0.65–0.8 caps it at 75 %, below 0.58 at 20 %); the sample values must fit the field (e-mail needs @, IBAN, SWIFT, currency, dates, postcode, phone and amounts have patterns), otherwise the suggestion is dropped.
  • Values like 1, 2, 3 look like a sort order: at most 30 %. Key fields (mandate, debtor, address numbers) never above 40 %: confirm by hand.
  • Suggestions below Hide suggestions below (0.35) are not shown. Every model call is listed (time, task, provider, model, items, seconds, result).
Never accept an operating company, an exclusion or a compliance matter on the model's word: check it. The assistant does not decide risk or KYC.

5. Using it

  • AI assistant tab: model status, Run all, Suggest decisions, Classify documents, Summary; the table of suggestions with Accept; document types and KYC gaps; model calls; AI settings.
  • While the assistant works, a bar shows how far it is, from 0 to 100% with one decimal, the batch it is on and about how long the step still takes. The percentage moves batch by batch: one long model call (the summary) holds it still until the answer comes. Stop ends the job after the current batch; tasks already finished keep their results. Needs decision shows the same percentage on the AI is thinking… button.
  • Nothing starts over. Every model answer is saved the moment it comes back (runs/ai_cache.jsonl, readable by you only). When a job is stopped, fails, or is cut off because the tool or the machine restarted, the AI tab says so with the percentage it reached and a Resume button: it runs only the tasks still open and takes the saved answers instead of asking again. Pressing Run all again reuses them too. A new run of the same exports reuses them as well, as long as the model is the same.
  • Memory. The local model needs several GB. Before loading it the tool checks the free memory and, when it is short, says how much is missing instead of starting: close browser windows and press Resume. When a job ends, the model is unloaded at once instead of staying in memory for five minutes (Settings unload_after, memory_check). The page shows the first 300 documents and the counts; every file is in Archive_KYC_coverage.xlsx and the review workbook.
  • Classify documents asks the model once per name pattern: same folder, same file name with the numbers masked (Letter 2021 and Letter 2022 are one question). The most common patterns go first, up to Most document names for the model per run (Settings, default 1,000, about 40 batches). The rest show as not classified: over the limit; raise the limit and run again to type more.
  • Needs decision: Ask AI, and a AI hint with Accept next to each item that has a suggestion.
  • Overview: the AI summary of the run.
  • Setting Run the assistant by itself after every migration run.
  • Terminal: bin/m2ctl.sh ai status, bin/m2ctl.sh ai all (last run) or bin/m2ctl.sh ai suggest runs/<stamp>. Result file: runs/<stamp>/ai_suggestions.json.

6. Claude Code (MCP server)

m2_mcp.py lets Claude Code work with the tool through the running UI, so the browser, n8n and Claude see the same runs and settings. In /data/migration_script it is registered by .mcp.json; elsewhere: claude mcp add m2-migration -- /data/migration_script/bin/m2ctl.sh mcp.

ToolDoes
m2_statusUI health, last run, model status
m2_runs, m2_summaryRuns and their totals
m2_runStart a run (default: the folder last used) and wait for it
m2_open_decisionsWhat blocks rows, grouped like Needs decision, with the AI suggestion of each item
m2_journal, m2_recordJournal events by rule, level, key or text; the full trail of one mandate
m2_ai_assistRun the local assistant and return its result
m2_decideRecord a decision in the settings (only after the user said yes)
ollama_askHand a question over client data (review items, document index, totals) to the local model
