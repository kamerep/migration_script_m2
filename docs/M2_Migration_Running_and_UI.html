M2 Migration – Running and the UI

The migration turns the M2 Mandat exports into the CSP client import workbook and records every decision it takes. Nothing is written to Odoo.

1. Export from M2

From each M2 function (Addresses, Mandates, officers, beneficial owners, share register, bank details, signatories, contact persons, Fees, open items) export the list to Excel or CSV into one folder. Keep the column headers; report titles above them are fine.

With the English M2 interface (Infosystem › Mandate info) the grid titles are read as they are: Mandate overview, Address, Detail addr., Bank / Account / Authorized to sign, Fees, Invoice, Compliance, Document. A grid exported for one mandate has no mandate column: name the file after the mandate, e.g. KP-482-ACC Detail addr.xlsx. Copy M2's document folders (named after the mandate number) next to the exports to have the files indexed per client.

2. Start the tool

.venv/bin/python m2_ui.py opens http://127.0.0.1:8796 (the next free port when it is taken). Choose the folder with Browse… (the picker shows how many export files a folder holds), or open Sample data and pick German headers or English M2 grids to try it with fictitious exports, then press Run migration (Ctrl+Enter).

3. Watch the run

The strip under the toolbar shows the eight stages (read & classify files, build clients, link registers, fees & open items, compliance, documents, template checks, write files) with a progress line, the event count and the time taken, and live counts per level: click a count to see those events. The Journal follows the events as they are written. The browser tab shows the percentage while a run goes, and a message at the bottom right tells you when it ends, with a button to the next step.

LevelMeaning
ErrorData that cannot be used as it is (unreadable file, duplicate mandate number, crash).
To reviewA row left out of the import file, with its reason and fix.
WarningLoaded, but worth checking (IBAN check digits, amount without currency, close call on a file kind).
DecisionA choice the migration made and why (address linked by debtor number, function routed to Directors, rows merged).
ChangeA value converted or cleaned (country name to ISO code, Swiss amount, date format).
Not loadedAn M2 value with no CSP column, kept in the review file and the client's Notes.

4. Decide

Needs decision lists what blocks rows: the operating company of each mandate holder (never a default company), employee abbreviations, the M2 Detail addr. type codes (which register sheet each fills), unrecognised files, unmapped columns and register rows whose client was not found. Each section says whether it blocks rows or is optional, and the bar at the top counts the decisions saved. Each answer is saved to m2_config.json and marked with a green tick; Undo takes it back. Run again starts the next run with them.

5. Trace a record

Click any M2 key (for example M-0001) to open Records: every event of that mandate across all files, in order, with the row it finally has in the import file or the reason it waits in review.

The Link button copies the address of that record (#records/M-0001) to paste into a ticket or a message.

6. Load into Odoo

Download CSP_Import_M2.xlsx from the Overview and load it in Contacts › Configuration › Client Import (Check, then Import). Fix the rows of CSP_Import_M2_Review.xlsx, paste them into the import file and load again: the M2 Reference makes every load an update.

7. Finding your way in the page

WhereWhat it is for
Side barThe sections in three groups: Run (Overview, Needs decision, AI assistant), Inspect (Journal, Records, Files & columns, Review rows, Changes & not loaded, Finance) and Configure (Settings, Docs). The button at its foot folds it to icons. On a phone or a window narrower than 900 px the side bar becomes a top bar: the button with the current section's name opens every section as a list.
Needs decision countRed: decisions you can save here (company, employee, file kind, column, type code) that are not saved yet. Grey: nothing to save, only items fixed at the source (in M2 or in the review file, then run again). The Overview says both, e.g. Needs decision: 2 decisions to save, 194 to fix at the source.
Tool decisionsThe card and the count in the run bar: choices the migration made by itself and wrote to the journal (level decision), e.g. an archive folder linked to a client. Nothing to do; open them to check.
Search and commands (Ctrl+K)Type a section, a mandate number or name, a rule, a guide or a command (Run migration, Switch theme, Download…) and press Enter.
Messages (bottom right)Green: done. Amber: needs your attention. Red: failed, and stays until closed. A message about a saved decision carries Undo.
LoadingA thin bar at the very top while the tool is asked something, grey placeholders while a section loads, a spinner on the button that is working. If the tool stops answering, a banner says so and the page reconnects by itself.
DocsThese guides inside the tool, with search, plus reference pages built from the code: HTTP API, MCP tools, command line, keyboard and links.
Theme and coloursLight, dark or as the system, and five colour palettes (Aubergine & lavender, Mauve & sage, Forest green, Lime & indigo, Rose & sky): the buttons at the foot of the side bar, or Settings › This browser. The side bar, the count cards, the buttons and the tab icon follow the palette; the level colours (error, review, warning…) stay the same in all of them.

Keys: / focuses the search of the section, [ and ] move between sections, 1–0 jump to one, ↑ ↓ step through events while the details are open, Esc closes, ? lists them all. The first Tab on the page offers Skip to content. Unsaved changes in Settings › All settings (JSON) are never lost silently: leaving the section or closing the tab asks first. The page follows Windows high contrast and the system's “more contrast” setting. When the source folder holds an archive inventory, the Overview shows its progress per mandate holder (see the Archive Inventory guide).

Files of a run

Each run is kept in runs/<stamp>/: the two workbooks, journal.jsonl, summary.json, run.log and the config.json it ran with, plus brief.json (totals and levels for the run selector, so the list opens at once even when a summary is tens of MB). Earlier runs open from the run selector.

Terminal

.venv/bin/python migration_script_m2_odoo.py <folder> [<output>] [--config m2_config.json] [--quiet] prints the same journal; the exit code is 1 when there are errors.

Portwatch: deploy and monitoring

The UI is watched by Portwatch as M2 → CSP Migration (port 8796, group Tools): a health check on /health, the server log logs/m2_ui.log (UI start, every run start and result, failed requests), Start / Stop / Restart, and the actions Deploy (unit tests, then restart on the new code, then health check; it stops at the first failure), Run tests, Status, Last run summary, Migrate last folder and Sample run. The same commands work by hand: bin/m2ctl.sh start|stop|restart|status|test|deploy|sample|migrate|last.

AI assistant, Claude Code and n8n

The AI assistant tab proposes decisions for a finished run with the local model (Ollama), types the documents and writes a summary; Needs decision shows an AI hint with Accept next to each item it has a suggestion for. Claude Code can drive the tool through the MCP server (bin/m2ctl.sh mcp), and n8n can run it on a schedule. See M2 Migration – AI Assistant, M2 Migration – n8n Workflows and M2 Migration – Archive Inventory.
