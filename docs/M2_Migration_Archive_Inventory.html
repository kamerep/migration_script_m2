M2 Migration – Archive Inventory

The M2 document archive (drive Z: “M2 Archiv”, e.g. Z:\NOVA-PH) keeps one folder per mandate: KP-00031-ENT, KP-00035-ACC, … When the M2 database itself cannot be shared, the folder structure still tells which client has which documents. The archive inventory reads only that structure: path, size and date of every file. No file is opened or copied.

1. Make the inventory (Windows)

Copy tools\m2_archive_inventory.ps1 to the Windows machine and run:

powershell -ExecutionPolicy Bypass -File m2_archive_inventory.ps1 -Root 'Z:\NOVA-PH'

It writes Documents\M2 Archive inventory.csv (or the path given with -Out) and prints the number of files and folders. -Root 'Z:\' lists every mandate holder folder of the drive in one file. Only files inside folders are listed: loose files of the root (such as the Archive (L) - Verknüpfung shortcut), shortcuts (.lnk), Thumbs.db, desktop.ini and Office lock files are left out.

From the Linux PC over Remmina, with the project's m2_db folder shared to the session (it shows as m2_db on PK):

powershell -ExecutionPolicy Bypass -File '\\tsclient\m2_db\m2_archive_inventory.ps1' -Root 'Z:\' -Out '\\tsclient\m2_db\M2 Archive inventory - all mandates.csv'

Keep one inventory per run folder: a holder listed in two CSVs is counted twice.

The CSV is written while the listing runs, holder after holder: a run started before PowerShell prints … files in … folders sees only part of the drive. To catch that, put archive_holders.txt beside the CSV, one mandate holder per line (lines starting with # are comments; spaces and hyphens are ignored, so NOVA-PH2 matches the folder NOVA-PH 2). The run then warns about every holder the inventory lacks. The file stays with the data, outside the repository.

Watching the listing. The script writes rows straight into the CSV, holder after holder, and shows a progress bar per holder in the PowerShell window. In the UI, Overview › Archive inventory follows the CSV of the source folder every 5 seconds: a bar of the holders done, then one chip per holder of archive_holders.txt, done (tick, files), being listed (spinner, files so far) or waiting, the files in all and the time of the last write. When nothing has been written for two minutes the card says complete, or stopped when holders are still missing. It warns about a second inventory CSV in the folder (holders counted twice), and Run migration asks before starting while the listing is still running. Writing to \\tsclient\… over the remote desktop is slow; for speed, write to a local disk and copy the finished CSV (the card then only shows the end).

Resuming a broken listing. If the listing stops (for example Export-Csv : The operation was canceled when the remote-desktop link drops), list only the holders still missing with -Holders, including the one it stopped in:

powershell -ExecutionPolicy Bypass -File m2_archive_inventory.ps1 -Root 'Z:\' -Holders 'NOVA-SG','ORBIT-CH' -Out "$env:USERPROFILE\Documents\M2 Archive inventory - part 2.csv"
Copy-Item "$env:USERPROFILE\Documents\M2 Archive inventory - part 2.csv" '\\tsclient\m2_db\'

Leave the first CSV where it is: the run reads every inventory in the folder, a file listed in both is indexed once, and the card combines them (the holder that was cut off shows partial until the second file lists it in full).

Without the script, the same in one line:

Get-ChildItem 'Z:\NOVA-PH' -Recurse -File | Select-Object @{n='Path';e={$_.FullName.Substring(3)}}, Length, @{n='Modified';e={$_.LastWriteTime.ToString('yyyy-MM-dd HH:mm')}} | Export-Csv "$env:USERPROFILE\Documents\M2 Archive inventory.csv" -NoTypeInformation -Encoding UTF8

2. Use it

Put the CSV in the folder with the M2 exports (or alone in a folder, for an archive-only run) and run the migration. The file is recognised as Archive inventory (file list) by its headers Path, Length, Modified (also FullName, LastWriteTime).

Path in the inventoryRead as
NOVA-PH\KP-00031-ENT\KYC\Passport.pdfMandate KP-00031-ENT = KP-31-ENT (zero padding ignored), holder archive NOVA-PH, sub-folder KYC
NOVA-PH\KP-00054-ACC\scan.pdfMandate KP-54-ACC, no sub-folder
NOVA-PH\Thumbs.dbNot under a mandate folder: not indexed (one warning per folder)
Archive (L) - Verknüpfung.lnkLoose file of the root or shortcut: skipped

3. Rules

RuleLevelMeaning
ARCHIVE_FOLDERdecisionFolder linked to a client of the exports; its files are indexed
ARCHIVE_FOLDER_UNKNOWNwarning (info in an archive-only run)Folder named like a mandate, but not a mandate of the exports (closed, or exported under another number); indexed under the folder name
ARCHIVE_NOT_MANDATEwarningFiles not under a mandate folder
ARCHIVE_NO_FOLDERwarningOpen mandates of the exports with no archive folder
ARCHIVE_HOLDER_MISSINGwarningMandate holders of archive_holders.txt with no file in the inventory: the listing has not finished, or covered only part of the drive. Shown under Needs decision
ARCHIVE_HOLDERS / ARCHIVE_HOLDER_EXTRAinfoEvery expected holder is there / folders on the drive that the list does not name
ARCHIVE_COPYinfoFiles identical to a file of the same mandate already indexed (same sub-folder, name and size), e.g. in an older copy such as NOVA-PH 2\NOVA-PH: indexed once. Files only in the copy are kept, under the copy's holder.

The mandate holder is always the top folder of the drive, also when the mandate folders sit one level deeper (NOVA-PH 2\NOVA-PH\KP-00252-ENT → holder NOVA-PH 2).

The files appear in Finance › Documents and in the Documents sheet of the review workbook with “On disk” = archive: …. AI assistant › Classify documents then types each file and lists the mandates missing documents (all on this machine).

4. Coverage across the mandate holders

A mandate number has exactly one extension, and the same mandate, with its registers and files, can be filed under any of the mandate holders (NOVA-PH, NOVA-DUBAI, ORBIT-CH …). Coverage is therefore judged per mandate over every holder it appears under: a passport in NOVA-DUBAI\KP-00031-ENT counts for NOVA-PH\KP-00031-ENT too.

ExtensionMandateNeeds (each line: one of the types)
ENTEnterprise, mainly companiesincorporation · register extract or articles · KYC / compliance file · passport or ID of a director or UBO
ACCAccounting services (invoicing)as ENT
CONNatural person, consultancypassport or ID · proof of address · KYC / compliance file
DIRDirector (rarely used)as CON
ADMInternal company (one of the mandate holders)not checked: status internal
otherany other extensionnot checked: status type unknown

A folder named KYC, Compliance, Due diligence, CDD or GwG counts as the KYC / compliance file. The check writes Archive_KYC_coverage.xlsx in the run folder:

SheetContent
MandatesOne row per mandate: type, status (complete, gaps, internal, type unknown), holders, files, what is missing in every holder, and what is missing in one holder but found in another
Where foundEvery file with its holder, document type and folder
Per holderPer mandate holder: mandates, complete, with gaps, internal, type unknown, shared with another holder
The inventory holds client names in file names: keep it on internal shares, like the exports.
