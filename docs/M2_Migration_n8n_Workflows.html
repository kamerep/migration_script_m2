M2 Migration – n8n Workflows

n8n runs on this machine and drives the migration UI through its API: a scheduled or webhook-triggered run, the local AI report, and a document classifier on Ollama.

1. Install and start

n8n/m2-n8n.sh install    # once: npm install in ~/.local/share/n8n-app
n8n/m2-n8n.sh import     # the workflows of n8n/workflows
n8n/m2-n8n.sh start      # http://127.0.0.1:5678 (the next free port when taken)

Open n8n, create the owner account on the first visit, open each workflow and switch it Active for its schedule and production webhook. stop, status, logs and run-report work the same way. Data: ~/.local/share/n8n-data; log: logs/n8n.log.

The script gives n8n: the UI address and its API token (bin/m2ctl.sh token), the Ollama address and model, write access to runs/ only, and listening on 127.0.0.1 only. The migration UI must run (bin/m2ctl.sh start).

2. M2 migration – run and local AI report

TriggerManual run, Weekdays 07:00, or Webhook m2-run (POST /webhook/m2-run, body {"source": "/path/to/exports"} optional)
SettingsUI address, token, source (webhook body, M2_SOURCE, else the folder last used in the UI), AI tasks
Start run → Wait for run → Run state → Still running?Starts the migration and polls every 3 s until it ends
Ask the local AI → Wait for AI → AI state → AI still working?Suggestions, document types and summary on Ollama, polled every 5 s
Final summary → Format reportMarkdown report: status, headline, totals, next actions
Save report / Answer webhookruns/<run>/n8n_report.md; JSON answer to the webhook caller

From the terminal: n8n/m2-n8n.sh run-report or n8n/m2-n8n.sh run-report '{"source": "/data/m2_exports"}'. To send the report, add an e-mail or chat node after Format report: the text is in report, the status in status.

3. M2 documents – classify by name with Ollama

curl -X POST http://127.0.0.1:5678/webhook/m2-classify -H 'Content-Type: application/json' \
  -d '{"files": ["KP-00031-ENT/KYC/Passport.pdf", "KP-00031-ENT/scan_0003.pdf"]}'

Keyword rules first, the rest to Ollama (/api/chat, JSON format, temperature 0); answer {"documents": [{"file", "type", "confidence", "by"}]}. File names carry client names: this flow never calls the cloud.

4. API used by the workflows

CallDoes
POST /api/run {"source", "last_source": true}Start a run
GET /api/summary?run=State, totals, levels, rule counts, AI summary
POST /api/ai/run {"run", "tasks"}Start the assistant
GET /api/ai?run=Assistant state and results
GET /api/ai/status, POST /api/ai/settingsModels and AI settings
POST /api/decideRecord a decision

Every call carries X-Token: <token> or Authorization: Bearer <token>. The token is in .m2_api_token (made once, 0600, not in git) or M2_API_TOKEN.
