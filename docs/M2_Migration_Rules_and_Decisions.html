M2 Migration – Rules and Decisions

The rules the migration applies, with the rule code shown in the journal.

Reading the files

RuleWhat happens
KIND, KIND_UNKNOWN, KIND_OVERRIDEA file is scored against every export kind: each header matched +1, key columns +2 more, words of the file name +4. Below 4 it is not read; a lead of 1 or less is a warning. Settings › file kinds forces a kind.
HEADER_ROW, ROW_TOTALReport titles above the header and total lines are skipped.
COLUMN, COLUMN_UNUSEDEach header is matched to a field by its German or English names (exact first, then partial), including the English grid titles of M2 Professional (Mandate desig. 1, CDB / SSB, Mad.Company, Firma / Name, Adrno., Date from / till, H.Type, OP No., Open amount foreign…). Unused columns keep their values in Not Loaded; Settings › extra aliases maps them.
REF_FROM_FILE, NO_CLIENT_COLUMNA grid exported for one mandate (Detail addr., Bank, Fees) has no mandate column: the mandate number is read from the file name (KP-482-ACC Bank.xlsx) or the report title, and every row belongs to it. There, Adrno. is the person's or bank's own address, not the client's. Neither found: warning, the rows cannot be linked.
HEADER_LABELSA row under the header that describes the columns (CLIENT NUM under MNR, JURISDICTION under MANDBEZ2) is read as labels, not as a client. A column whose label names a field the header did not give takes it; for the jurisdiction it is a second source.
ROW_NOTEA row with a single value that is not a number or a name (a filter or legend under the table) is a note, not a client.

Clients (mandates)

RuleWhat happens
REF_COMPOSEDA mandate list exported straight from the M2 database has no mandate number column: the number is built from prefix MT, number MNR and type MART (KP-00031-ENT). MADFIRMA is the mandate holder, MANDBEZ1 the name, VSB the responsible employee, MANDATS_BEGINN / MANDATS_ENDE the contract dates. An empty column never takes a field from a filled one, and its exact name keeps the field from a look-alike column (an empty STATUS does not hand Status to STATUS_MUTDATUM). The assistant never proposes a date column for a number or text field.
CLIENT, REF_FALLBACKOne client per mandate; the M2 Reference is the mandate number (else debtor, else address number). M2 numbers are compared without their zero padding: KP-00482-ACC = KP-482-ACC.
DUPLICATE_REFA mandate number twice: the second row goes to review.
ADDRESS_LINK, VALUE_CONFLICTThe address is found by address number, debtor number, the debtor number as the address Number (in M2 the debtor is an address), then exact name; a value that differs between mandate and address keeps the mandate's. Postcode, City printed together (MH 96960 Majuro) is split into country code, postcode and town; Founded and Business activity come from the address.
TYPEKLI (client / person) → Individual; GES → Company.
ENTITY_TYPEAG, GMBH, LLP, LTD, FZCO… → company; STI / Stiftung → foundation; TRU, VTR → trust. Anstalt is flagged to check.
COMPANY, COMPANY_UNKNOWNThe mandate holder is mapped to an operating company. Unknown holder: review, never a default company. The import file gives the company's CSP Short Code (the first holder mapped to it, e.g. ARVIS-PH), which Odoo matches on the company's CSP tab; the review file shows the name.
VALUE_CHANGED (Jurisdiction), JURISDICTION_DIFFERSJurisdiction of incorporation, loaded into Odoo's Jurisdiction: JURISDIKTION_STAAT_TXT first, then a column labelled JURISDICTION (MANDBEZ2), then the domicile (DOMIZIL_STAAT_TXT); the first that reads as a country. German names (Britischen Jungferninseln, Vereinigte Staaten von Amerika, Russische Föderation …) and "Republic of …" are read; "Kein Land" is empty. When the sources name different countries the first is kept and a warning lists the others.
EMPLOYEE_UNKNOWNAn M2 staff code (VSB, SSB: FF, AN …) not in Settings › employee map leaves Client Advisor / Deputy empty and is listed in Needs decision; a code is never written to the import file, where Odoo would reject the client. A full name passes as it is.
EMPLOYEE_UNKNOWNAdvisor / deputy abbreviations through the employee map; unknown ones are left empty and listed.
MANDATE_CLOSEDClosed status, Active = N or past end date: not loaded (switchable); its register rows follow.
UBO_FROM_MANDATEThe beneficial owner named on a mandate becomes a UBO entry, merged with the UBO export.

Registers

RuleWhat happens
OFFICER_ROUTE, OFFICER_IGNOREDA combined officers list (M2 Detail addr.) is split first by its Type code through Settings › officer types (e.g. DIR → Directors, BO → UBOs, CP → Contact persons, or ignore), then by the wording of the function: Verwaltungsrat, director, Geschäftsführer, Stiftungsrat → Directors; secretary → Secretaries; agent → Agents; Bevollmächtigter, Vollmacht, attorney → Powers of attorney. Unknown → review, with a one-click choice in Needs decision. collective J/N → jointly / singly; Remark 2 and 3 join the Remark.
BANK_RELATION, BANK_AMBIGUOUSA Banks-grid row with a bank but no account number is the client's bank relationship: its bank name, clearing number (BCN) and BIC go to the client's accounts when it has one bank; with several the bank is left empty (warning). An account with no currency column takes the ISO code in its type or remark (Current account USD).
LINK, CLIENT_NOT_FOUNDClient found by mandate no → debtor no → address no → exact unique name. Close names are suggested, never chosen.
CLIENT_IN_REVIEW, CLIENT_CLOSEDA row follows its client into review or out with a closed mandate.
ROW_INVALIDNo name, the client's own name as the person, end before start, bank account without number or currency.
MERGEDRows of one person at one client become one entry; other periods go into the Remark.
IBAN_CHECK, SWIFT_FORMATIBAN check digits and BIC format are verified (warning).

Values

ValueConversion
DatesDD.MM.YYYY, YYYY-MM-DD, DD/MM/YYYY (or MDY in Settings), Excel day numbers, 2-digit years; impossible dates are not loaded. Day-month only (financial year end) gets the current year.
Amounts1'000.00, 1.000,00, 1,000.00 and a currency in the text (CHF 100'000).
CountriesISO2, ISO3 and German, French and English names (Schweiz, VAE, Hongkong, BVI…).
Names"Surname, Given name" → "Given Surname"; given name + surname columns joined.
SigningEinzel… → singly; Kollektiv… / zu zweien → jointly.
OwnershipA fraction 0–1 becomes a percentage; 0 % is read as not known.

Finance

FEE rows (ABF, FLF, LEI) and OPEN_ITEM rows are not client-template data. They are listed in the review file; open items are totalled per operating company and currency for the reconciliation after the opening items are posted.

RuleWhat happens
FEE_ENDEDA fee with a past finish date is listed as ended, not for the subscriptions.
LEI feeThe due date of the LEI fee fills the client's LEI Renewal Date (LEI_RENEWAL_CONFLICT when another fee says otherwise).
OPEN_ITEM_PAID, OPEN_ITEMS_PAIDM2's invoice list also holds paid invoices: those with nothing open are left out of the receivables. The open amount in the invoice currency (Open amount foreign) is used; a paid flag with an amount still open is a warning.

Powers of attorney

RuleWhat happens
KINDA Vollmachten export (headers such as Bevollmächtigter, Vollmachtsart, Gültig ab / bis, Widerrufen am) is read as Powers of attorney and goes to the Powers of Attorney sheet. The client is found as on every register (mandate no, debtor no, address no, exact name; Vollmachtgeber counts as the client name).
VALUE_CHANGED (Type)The M2 kind becomes a Type: Bankvollmacht → Bank, Generalvollmacht → General, Handelsregister → Registry / Corporate, Prozessvollmacht → Litigation, Spezial / Einzel → Special. Any other kind is Other, and the M2 wording is kept in Scope.
POA_STATUSStatus from the dates: a revocation date (or Widerruf = J) → Revoked; Valid Until in the past → Expired; otherwise Active. A row without an attorney stays Draft.
ROW_INVALIDValid Until before Valid From, or the client's own name as attorney: the row goes to review.
POA_FROM_ARCHIVEA file of the M2 documents or the archive whose name or folder says Vollmacht or attorney gives one Draft entry per document (pdf and docx of the same document count once), for a loaded client with no power of attorney in the export. Its M2 Reference is the archive path, so a new run updates it instead of adding it again. Complete the attorney, scope and dates in Odoo from the document. A bare "POA" is Proof of Address and gives no entry.
POA_REVOCATION_FILEA revocation (Widerruf, revocation) in the documents gives no entry: review it and mark the power of attorney it revokes as Revoked in Odoo.

Compliance and documents

RuleWhat happens
COMPLIANCE, COMPLIANCE_LOCKML-related, risk category, country of max. risk, lock and note have no template column: they go unchanged into the client's Notes and the Compliance sheet. A lock is a warning to clear with compliance. The tool never decides a risk rating.
DOCUMENT, DOCUMENTS_FOLDER, FOLDER_NOT_CLIENT, DOCUMENTS_MISSINGThe M2 document export and the sub-folders named after a mandate number (M2's document store) are indexed per client in the Documents sheet, with the path of each file to attach in Odoo.
Every rule writes its event with the source file and row, the M2 key, the values before and after, and how to fix it.

Archive inventory rules

RuleMeaning
ARCHIVE_FOLDERAn archive folder named after a mandate number (zero padding ignored) is linked to that client; its files are indexed.
ARCHIVE_FOLDER_UNKNOWNFolder named like a mandate but not in the exports: indexed under its folder name (warning; info in an archive-only run).
ARCHIVE_NOT_MANDATEFiles outside mandate folders: not indexed.
ARCHIVE_NO_FOLDEROpen mandates without an archive folder.

AI suggestions are not rules: they never change a run; an accepted suggestion is an ordinary decision in m2_config.json.
